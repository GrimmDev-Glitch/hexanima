# Qwen-Image 2.1 Turbo on the Hexagon NPU: sources

Everything needed to rebuild the Qwen-Image pack and the native parts (text-to-image and photo editing). Weights are not here; the models are Qwen team / LightX2V / Unsloth works (Qwen Research License for the transformer, adapter and VAE: **non-commercial**, Apache-2.0 for the Qwen3-VL text encoder), see `../THIRD_PARTY.md`. The converted pack is downloaded by the app.

- `NOTES.md`: working notes (findings, kernel port design, numerics, speed passes, pitfalls).
- `qref.py`, `qwen_ref.py`, `qwen_te_ref.py`, `qwen_e2e_ref.py`, `qwen_edit_ref.py`, `vit_ref.py`: PyTorch/numpy references used to check every kernel (GGUF loader, DiT block in kernel form, text encoder, ViT, whole pipeline, editing).
- `export_qwen2.py` (DiT pack v2, current), `export_qwen.py` (v1), `export_qte.py` (text encoder), `export_vit.py`, `export_qglue.py`, `export_vae_qwen.py` / `export_vae_enc.py` (+ `vae_q/build_vae.sh`, QAIRT) , `packio.py`, `fetch_visual.py`; `../tools/make_qwen_pack.py` writes the manifest, `pack/` holds the README / NOTICE / LICENSE that go to the pack repository.
- `hexagon/mega/`: DSP side (generalisation of `../hexagon/mega`): mode 40 DiT block with a block-causal mask, mode 22 text-encoder layer (HMX attention), mode 23 ViT layer. Needs the Hexagon SDK and QHL HMX sources (Qualcomm files, not included).
- `qwenrun/`: `qwenrun` (`cat head.inc body.inc > qwenrun.cpp`: tokens -> ViT -> text encoder -> 4 DiT steps -> latent, weights streamed from flash, prefix and text caches), `vaetile` (tiled decoder), `vaeenc` (tiled encoder for the photo), `build.sh`.
- Qwen runtime LoRA: `qwenrun` accepts `QWEN_LORA=/path/to/overlay-dir`; `make_qwen_overlays.py BASE_PACK FUSED_PACK OUT_DIR` compares packed DiT blocks and `glue.bin` in 4 KiB chunks and writes sparse `blkNN.ovl` and `glue.ovl` records. The shared parser in `qwenrun/overlay.h` validates records before patching; the runner also requires the original glue header to remain intact. `export_qwen_lora.py FUSED_PACK LORA.safetensors SCALE` combines a user adapter with the built-in Lightning LoRA and writes a tuned `glue.bin` for global layers such as `modulation.1` and the timestep embedder. It recognizes Diffusers/PEFT and Kohya key variants, applies alpha/rank scaling from tensors or uniform PEFT metadata and rejects unsupported targets, per-layer alpha patterns or incomplete pairs. The Civitai consistency adapter `qwen21_consistency_v1` was exercised in a masked photo edit; it did not visibly improve the four-step Lightning route and remains experimental. A separate Civitai download, PC conversion, ZIP import and on-device generation were verified with Lenovo UltraReal Qwen 2.1: 32 blocks and `glue.ovl` imported after hash validation, and the four-step run produced a recognizable red apple in 41.6 s. See `../docs/screenshots/qwen-civitai-lora-test.png`. Viggle is a *distillation* adapter for the Qwen base; because the installed pack already contains Lightning, it should not be stacked without a dedicated quality test.
- `bash convert_civitai_lora.sh LORA.safetensors [strength] [pack-name] [trigger-words]` automates host-side Qwen 2.1 Turbo conversion and emits a hash-described V73 overlay folder plus `.zip`. The app's Civitai browser downloads the Safetensors and a matching JSON sidecar to `Downloads/HexAnima/Civitai`. Transfer both files to the PC and run this converter; when explicit trigger words are omitted, it reads the Civitai `words` array from the sidecar. Import the resulting ZIP in HexAnima Dev. The converter checks for the pinned GGUF, Lightning adapter, transformer and VAE configs, and 32 matching `phone_base` blocks; the exporter rejects unsupported keys and shapes. If needed, fetch the two small configs with `python3 fetch_converter_inputs.py transformer-config vae-config`. Imported overlays are hash-checked against the pinned V73 base-pack fingerprints. Raw Safetensors cannot run directly on the phone.
- `mk*.py`, `cmp_q.py`, `test_pack.py`, `check_vae_*.py`: laptop-side drivers that run the kernels on a phone over adb and compare with the references.

The app bundles `qwenrun`, `vaetile`, `vaeenc` and the DSP skel through `../tools/stage_jnilibs.sh` (set `QWEN_DIR` to this directory). On SM8550 / V73, the Qwen VAE decoder and encoder are architecture-specific companions: run `../tools/make_qwen_v73_pack.py vae_q/out_v73 artifacts/qwen_v73` from this directory to stage the checked contexts, manifest, license and notice for `GrimmDev-Glitch/hexanima-packs/qwen_v73/`. The decoder is pinned to the adaptive-RMS binary validated against a real transformer latent. The app probes and validates this manifest before enabling Qwen download, then verifies file sizes and hashes during installation.
