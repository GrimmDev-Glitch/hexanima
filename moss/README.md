# MOSS-Image on the Hexagon NPU: sources

Everything needed to rebuild the MOSS-Image pack and the native parts. The weights are not here (they are Apache-2.0 models by OpenMOSS, Qwen, Black Forest Labs, Unsloth and darask0, see `../THIRD_PARTY.md`); the converted pack is downloaded by the app.

- `NOTES.md`: working notes (design, measurements, pitfalls).
- `moss_ref.py`, `qwen35_ref.py`, `sample_ref.py`, `pipeline_moss_image.py`: PyTorch references (the last one is OpenMOSS' own pipeline file) used to check every kernel.
- `export_*.py`, `make_lora_overlay.py`: GGUF / safetensors -> NPU tile packs (8-bit 32x32 tiles, the 4-step adapter kept as unmerged LoRA tiles); `upload_hf.py` pushes the pack (`../tools/make_moss_pack.py` writes its manifest).
- `hexagon/mega/`: the DSP side (HMX GEMMs, RMSNorm/modulation, SiTU, joint attention, Qwen3.5 delta-net layers) and its test harness `blk_main.c`. It is the generalisation of `../hexagon/mega` (Anima); build it the same way (needs the Hexagon SDK and QHL HMX sources, which are Qualcomm files and not included).
- `mossrun/`: `mossrun` (one process: tokens -> text encoder -> refiner -> 4 DiT steps -> latent, weights streamed from flash), `vaetile` (tiled FLUX.2 decoder for sizes without a ready context), `lorafold` (user LoRA check and on-device fold into the adapter slots) and `build.sh`.
- `*_test.py`, `cmp_blk.py`, `npu_*.py`, `lora_test.py`: laptop-side drivers that run the kernels on a phone over adb and compare with the references.

The app (`../app`) bundles `mossrun`, `vaetile`, `lorafold` and the DSP skel through `../tools/stage_jnilibs.sh` (set `MOSS_DIR` to this directory).

For an experimental Snapdragon 8 Gen 2 DSP build, run `ARCH=v73` in the Hexagon build container. This builds `hexagon/mega/out/libmega_skel_v73.so` with V73 HMX FP16 convert-store handling. On the connected SM8550, the GEMM smoke test passed (128×256×128, relative error 0.00028); normalization, residual add, GELU, softmax, RMS/RoPE and transpose tests also passed. A real MOSS DiT block using the official pack weights completed with `r=0`, `rc=0` in about 107 ms, and its output was finite with active residual gates.

The official Diffusers VAE under `moss/vae/` was exported to ONNX, converted with QAIRT 2.28 and compiled into a V73 context using `ARCH=v73 SOC_MODEL=43 SIZES=512x512 ./build_vaes.sh`. The context decoded a 512×512 tile in 273 ms. The full on-device pipeline then generated a 512×512 fox image in 18.18 s: text encoder 3.24 s, four DiT steps 3.5–3.8 s each, VAE 302 ms. The output had 786,432 finite FP32 values. Battery temperature was 37.4 °C after the run and Android thermal status remained 0. The phone test needs `libQnnHtpV73Stub.so` and `libQnnHtpV73Skel.so` beside the runner in its DSP library path.

MOSS V73 is now exposed as experimental in the device catalog. `tools/stage_jnilibs.sh` stages the MOSS runner, V69/V73 skeletons, VAE tile runner, and the tested V73 VAE context into the APK assets. At first generation, the app copies that architecture-specific context to `files/moss/vae_v73/`; MOSS weight packs remain architecture-independent. On a Poco F6 Pro (SM8550), the development APK copied the context and completed a 512×512 UI generation in 20.6 s. A live batch was increased from one to two while its first image was at step 2/4; both images were saved and the batch finished in 32.3 s. Stopping a later generation returned the UI to its ready state. Battery temperature after the two-image batch was 38.0 °C and Android thermal status was 0. The eight-worker DSP stress test hung; the app's current MOSS path uses three workers, and the real block test passed at that setting. Long sustained thermal runs and other size presets remain unverified.
